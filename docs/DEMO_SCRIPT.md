# commit — Three-minute pitch script

| Time | Action | Script |
| --- | --- | --- |
| 0:00–0:20 | Show landing Try it demo | Open-source maintainers can have urgent issues, but a contributor often cannot see whether a reward is real or who owns the work. commit creates a public, funded commitment for one small issue. Play the simulation: fund, claim, proof, payout receipt. |
| 0:20–0:50 | Maintainer create form | GitHub remains where code is discussed and reviewed. Here, the maintainer locks a small Testnet MON bounty, describes one acceptance condition, and publishes the commit on Monad. |
| 0:50–1:20 | Contributor claims in second browser | Before writing code, the contributor sees the bounty is actually locked. One wallet claims it, and the ledger changes for everyone immediately. |
| 1:20–1:50 | Contributor submits PR URL | After work happens on GitHub, the contributor records one public proof URL. We do not pretend the chain evaluates code. It preserves the human commitment and the proof of delivery. |
| 1:50–2:20 | Maintainer approves release | The maintainer reviews the PR on GitHub, then approves. The contract releases the Testnet MON and emits a receipt. |
| 2:20–2:45 | Show `/wall` updating | This board is reading confirmed Monad Testnet state and events, not a private database. Every state change is shared, public and durable. |
| 2:45–3:00 | Return to receipt | We used Monad Foundry for contract testing and deployment, plus Wagmi and Viem for direct reads, writes and event updates. commit makes small software commitments visible enough to act on. |
